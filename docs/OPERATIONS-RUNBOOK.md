# 运营与告警手册

- `/health/live` 失败：重启实例并检查启动日志。
- `/health/ready` 失败：检查 MySQL 网络、连接数、磁盘和迁移版本；不要把流量导入未就绪实例。
- 5xx 比例、P95 延迟、登录 429、文件失败、模型失败突增：按 `X-Request-ID` 查询结构化日志，先隔离影响，再回滚最近版本。
- 文件存储 75% 告警、90% 严重；数据库容量、备份年龄、证书到期和队列积压应由部署平台补充告警。
- 安全事件：冻结相关会话和密钥、保存审计证据、确认影响范围、通知负责人和受影响用户、修复后复盘。
- 每周：检查失败任务、待审核积压、找回与注销请求。每月：依赖更新、权限复核、备份恢复演练。每季度：隐私文本、数据期限和应急联系人复核。
- 每日先执行 `python backend/scripts/run_retention.py` 查看待清理量，确认后再用 `--apply` 清理过期会话、24 小时前的简历分片、30 天前已完成找回申请和超期审计日志；账号注销不由此脚本自动执行。
