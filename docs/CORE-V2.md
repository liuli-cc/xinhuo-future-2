# 薪火未来 Core v2 内核说明

## 1. 定位

Core v2 把平台从“展示型前端”升级为证据驱动的学生成长决策系统。系统的判断链路是：

`真实佐证 → 人工核验 → 五维能力画像 → 目标岗位差距 → 动态行动优先级 → 学生反馈 → 新佐证`

成长评分和行动推荐继续全部由可重复执行的规则引擎生成。模拟面试可由用户主动连接 DeepSeek、Kimi、智谱 GLM、通义千问、MiMo 或豆包官方 API，但外部模型只负责生成问题、追问和提取文本依据，不能修改最终分数，页面不会把模型输出包装成已经核实的学生事实。

## 2. 证据型成长评分 XH-EGM-2.0

五个能力维度为：专业学习、项目实践、创新探索、沟通协作、职业准备。

单条证据的基础强度：

```text
证据强度 =
来源可信度 × 能力相关度 × 成果质量 × 个人贡献度 × 时间权重 × 核验门槛
```

- 所有因子归一化到 `0—1`。
- 只有 `verified` 的证据核验门槛为 `1`，待审核和驳回均为 `0`。
- 180 天内时间权重为 `1`；之后按阶段降至 `0.9`、`0.78`、`0.65`。
- 同一种来源的第 2、3、4 条及以后证据分别按 `0.72`、`0.52`、`0.38` 进行边际衰减，防止重复堆材料。
- 不同来源交叉验证时，每增加一种来源给予 `4%` 多源奖励，最高 `16%`。
- 维度分数使用饱和曲线，避免线性累加超过 100，并使用可信度对原始分进行校正。

该算法是项目自行设计的“形成性评价与行动支持算法”，不是已经完成大样本常模验证的心理测量量表。因此页面只称“证据能力指数”，不称学生排名或绝对能力。若用于正式学校评价，需要在试点中继续完成评分者一致性、重测信度、内容效度和结果公平性检验。

## 3. 动态规划引擎 XH-DPE-1.0

平台内置探索方向、后端开发、算法工程师、数据分析、产品经理和升学科研六类目标画像。每类画像公开五维目标基准与权重。

行动优先级：

```text
优先级 =
(能力差距影响 × 35%
 + 目标相关度 × 25%
 + 时间紧迫度 × 15%
 + 可执行性 × 15%
 + 兴趣匹配 × 10%)
/ (0.84 + 行动成本 × 0.08)
```

输出同时包含当前分、目标基准、差距、权重、预计周期、验收物和每个影响因子。推荐反馈会保存到数据库，用于后续降低无效建议的重复出现频率；任务正式完成仍必须提交佐证并通过人工审核。

## 4. 混合模拟面试引擎 XH-SIE-1.1

面试不再按回答字数直接给分。单题提取：

- STAR 四要素是否出现；
- 是否包含数字、比例、周期等量化结果；
- 是否明确个人行动；
- 是否出现目标岗位工作关键词；
- 回答用时是否位于合理区间。

报告由内容质量 `35%`、逻辑结构 `25%`、岗位匹配 `25%`、表达效率 `15%` 合成，并保存逐题信号和改进建议。系统不做语音情绪、性格或心理状态推断。

API 模式采用“模型对话、规则计分”的分工：

- 外部模型根据目标岗位、难度和最近五轮真实回答生成下一题；
- 模型输出客观概括、有效信息、信息缺口、候选人原话证据和下一步考察重点；
- 候选人回答被封装为数据，不能覆盖系统面试规则；
- 模型输出不会直接加分或扣分；最终分数与同一回答在本地规则模式下保持一致；
- 模型连接失败时，本次面试自动降级到内置题库，不丢失已经完成的回答；
- API Key 只保存在 React 页面内存并随 HTTPS 请求临时传给服务端，不写入 PostgreSQL、审计日志或源码；
- 服务端只允许 DeepSeek、Kimi、智谱 GLM、通义千问、MiMo、豆包六家预设官方域名，不接受任意 Base URL，避免 SSRF 和开放代理风险；
- 结束面试、生成报告或刷新页面后需要重新填写 API Key。

## 5. 真实佐证文件

- 支持 PDF、DOC、DOCX、TXT、Markdown、JPG、JPEG、PNG、WebP、BMP，单文件最大 3 MB。
- 图片与扫描版 PDF 在浏览器本地使用中英文 OCR，扫描版 PDF 最多处理前 4 页。
- 文件二进制存储在腾讯云 PostgreSQL 的 `BYTEA` 字段中，不依赖学生电脑。
- 每个文件记录原始文件名、MIME、字节数、版本和完整文件 SHA-256。
- 下载接口执行登录鉴权；学生只能访问自己的文件，有审核权限的教职工才能访问审核范围内材料。
- 待审核证据可删除；已核验证据不能由学生自行删除。
- 审核结果、审核人、说明和时间进入不可见于学生修改入口的审核历史与审计日志。

当前方案适合比赛演示和早期校内试点。附件规模扩大后，应把二进制迁移到腾讯云 COS，仅在 PostgreSQL 保存对象键、哈希和版本元数据。

## 6. 组织角色与范围

角色包括学生、教师、辅导员、学院管理员、学校管理员和平台管理员。

- 教师/辅导员：可按学院和可选班级范围审核佐证。
- 学院管理员：管理本学院账号并审核学院材料。
- 学校管理员/平台管理员：全校范围管理、容量监控、账号恢复、注销处理和审计查看。
- 新建教职工账号只返回一次临时密码，首次登录必须修改。

## 7. 账号安全与数据权利

- 密码使用 PBKDF2-SHA256、随机盐和 310,000 次迭代；旧版 60,000 次哈希可兼容登录，修改密码后升级。
- 连续 5 次密码错误锁定账号 15 分钟。
- 会话令牌只以 SHA-256 摘要保存；支持查看设备、退出其他设备，修改密码自动撤销其他会话。
- 未接入邮件/短信供应商前，密码找回采用管理员辅助核验流程，避免伪造“已发送验证码”。
- 注册时记录明确的数据处理同意。
- 学生可导出个人 JSON 数据。
- 注销申请提供 7 天撤销期；到期后管理员可执行永久删除并保留最小化审计记录。

## 8. 仍需后续验证

- 在真实学生与教师试点中校准目标基准、能力权重和任务成本。
- 进行不同年级、专业和性别群体的差异影响检查。
- 为正式生产环境接入邮件/短信服务、恶意文件扫描和腾讯云 COS。
- 使用真实学生试点对六家模型的追问质量、输出稳定性、响应延迟和敏感信息处理进行对照评测。
