# 企业招聘与 AI 简历

学生入口 `/resume-ai`，企业入口 `/enterprise`，均沿用平台登录会话。

## 简历制作与导入

学生可编辑个人信息、教育背景、技能、项目与实习，保存后从账号恢复；导出支持三种配色的打印 PDF 和可编辑 Word。新增经历默认留空，导入或 AI 建议均需点击采用。修改草稿后，基于旧内容生成的 AI 建议不可覆盖新稿。

简历工坊与模拟面试共用导入流程：

- PDF、DOCX、TXT、Markdown：服务端提取正文，再按章节结构化。
- JPG、PNG、WebP、BMP 及扫描 PDF：浏览器运行中文与英文 OCR，再将识别文本发送到账号对应的结构化接口。
- 支持常见中英文标题、OCR 中文空格、项目描述与内嵌技术栈；保留多行经历描述。简历工坊同时导入识别到的联系方式、岗位意向与年级。
- 单个文件最多 3 MB；文字 PDF 最多 30 页，扫描 PDF 最多 4 页。超限给出错误，不截取前几页冒充完整结果。旧版 `.doc` 需另存为 DOCX 或 PDF。
- 文件签名、DOCX 正文大小、分片归属、分片总数与编码均校验。成功解析后删除上传分片；开始新上传时清理该账号超过一小时的遗留分片。

识别结果可预览后导入草稿，未识别字段保留已有值。OCR 可能仍有错字，所有字段均可继续编辑。

## AI 优化

沿用服务端模型网关：根据目标岗位优化简介和已有经历，并返回待补充建议。请求隐藏联系信息，不传姓名字段；提示约束不虚构学历、技能、数字、雇主或成果，不将团队成果写为个人成果。经历修改只能引用原有 ID，后端拒绝新增或重复 ID，以及无效输出。

AI 服务未配置、调用失败或输出无效时明确返回错误，原稿保留。编辑、保存、导出与投递不依赖 AI 服务开通。界面采用建议后仍须保存。

## 招聘流程

企业可发布、编辑、关闭和重新开放自己的岗位。学生选择企业后，可查看在招岗位的职责与要求；选择岗位并确认分享后，平台保存简历与勾选的已核验成长记录的投递快照。企业没有在招岗位时仍支持通用投递。

同一岗位防止重复投递，同一企业的不同岗位可分别投递。后续修改草稿不会改变既有投递；学生可撤回后重新投递。企业只能访问投递给本企业的资料。

企业工作台支持关键词与岗位筛选、查看简历、收藏、Word 导出、面试邀请、录用和不合适状态。面试邀请需填写未来时间及地点或线上会议方式，学生在“我的投递”查看面试安排及后续状态。撤回后企业无法继续通过平台访问该次投递。

## 初始化

在后端配置数据库连接后运行 `alembic upgrade head`。迁移 `004` 建立原投递表；`005` 增加企业岗位、按岗位投递与面试邀请字段，并迁移历史通用投递。前端沿用 `NEXT_PUBLIC_API_BASE` 与项目 HTTPS 部署设置。

管理员通过 `python scripts/bootstrap_admin.py --student-id 900100 --name 企业名称 --role enterprise` 创建企业账号，密码通过交互输入。公开注册不能获得企业权限。

## 验证

后端完整检查：`cd backend && .venv/bin/python -m pytest app/tests -q`。

前端检查：`cd frontend && npm run lint && npm run build -- --webpack && npm run test:unit`。

新增测试覆盖实际 PDF/DOCX 提取、中文 OCR 空格与章节边界、分片参数及账号隔离、导入字段保留、真实 Word 文件内容、AI 经历 ID 校验及原稿保留、证据分享范围。招聘集成测试覆盖企业岗位权限、不同岗位投递、重复投递、岗位关闭、面试邀请、结果状态、撤回与历史迁移。

本次浏览器检查还使用合成中文简历图片及不含文本层的扫描 PDF，实际运行 OCR、导入预览和 Word 下载，未替换 OCR 引擎。模型网关测试使用受控响应，不代表已经完成真实供应商联调。
