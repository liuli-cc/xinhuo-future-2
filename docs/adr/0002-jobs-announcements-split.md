# 岗位、校招公告及其投递/收藏全链路分表分页

招聘岗位与校招公告曾被提议放进一张 `job_postings` 池表（用 kind 字段区分），经讨论否决，改为**全链路分家**：岗位、公告各一张表；岗位投递、公告投递各一张表；岗位收藏、公告收藏各一张表；页面也各自独立（实习就业页内「岗位 / 校招公告 / 求职工作台」三个标签）。

原因：两者不是同一维度的东西——岗位是「一个具体职位」（有专业限制、要求原文，是智能匹配的对象）；公告是「一个公司的一次招聘动作」（内含多个岗位、只有届数和岗位清单文本，不做匹配）。硬塞一张表会产生大量可空字段和按 kind 分叉的 if 逻辑；分表后每个概念的字段都是完整的，页面职责清晰。代价是阶段机、时间线等规则存在两份**结构相同**的表——约束：这类共用规则必须收敛在一个模块里（同一套阶段/结束原因枚举与服务函数），两边只是存储分开，逻辑不许复制两份各自演化。

## Considered Options

- 单表 + kind 字段（否决：字段大量可空、查询与展示按 kind 分叉）
- 公告为父、岗位为子的父子表（否决：公告里的岗位清单是非结构化文本，拆解成本高，留待二期）
