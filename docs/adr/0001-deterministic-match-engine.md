# 匹配分数由确定性规则引擎裁决，AI 不参与打分排序

岗位大厅要按「匹配程度」排序展示，开发中曾提议直接用 AI（LLM）做推荐排序。我们决定：匹配分由确定性规则引擎（关键词规则 + 画像维度加权 + 硬性条件过滤）唯一裁决，AI 只承担两处辅助——导入岗位时把 JD 解析成结构化标签（无模型密钥时自动降级为关键词提取），以及生成匹配报告的解读文案。AI 的输出永远不进入分数。

原因：本平台定位是「证据型成长、可解释、AI 不能改写最终分数」，排序若交给黑盒模型，与全平台理念冲突且答辩时无法解释；线上环境可能没有模型密钥，核心功能不能依赖它；规则引擎可测试、可复现、离线可用。前端曾出现规则双份实现导致漂移的事故（前端 career-engine.ts 与后端 career/service.py 关键词表不一致），此 ADR 同时确认：匹配规则只存在于后端一处，前端只调接口展示。

## Considered Options

- 纯 AI 推荐（否决：不可解释、无密钥不可用、违背证据型定位）
- 纯规则、完全不引入 AI（可行，但 JD 结构化全靠人工，导入 900 条数据不现实）

## Consequences

- 分数可单测、可复现，排序在无网/无密钥环境下仍工作
- 匹配规则只许存在于后端 `career/service.py` 一处，前端禁止复制实现
- 若未来引入语义匹配（embedding 等），只能作为新的独立信号叠加，不能替换规则分数
